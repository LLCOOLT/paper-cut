# Web build: game-code issues for the decomp

The web build (WebAssembly; docs/PC_PORT.md, "Web") is stricter than x86-64
and arm64 in one way that matters for game code: **every call must match the
callee's real signature, and a function is never data.** A native linker
accepts both; wasm-ld refuses to link the first and turns the others into
traps. This is every place in JP (G8MJ01) and US (G8ME01) where the game code
relies on the looser rule, so the decomp can fix them; the fixes come back
here with the cleanup. Nothing below is changed in this repo.

All of them are undefined behaviour in C on every platform. Most are harmless
on GameCube and desktop only because of how those ABIs pass values: extra
arguments are ignored, missing ones and missing return values read leftover
registers. A few are visible bugs there too: `marioGetMoveRate` takes an
`f32` that party_yoshi.c never passes, so it reads whatever `f1` holds.

What happens today: both versions fail to link on section 1. With section 1
fixed, they link and US runs about 4,000 frames (boot, the opening sequences,
the `dmo` area) and traps at the first section 2 call it reaches, in
`marioStMain`.

Fixes, by section:
1. Declare the function as what it is: `USER_FUNC(name);` for a script
   function, `void name(MapTevCallbackInfo* info);` for a texture callback.
2. Make the declaration the definition's (better, include the header that
   declares it), and drop or add the argument at the call. Where a caller
   uses the value of a `void` function, it read leftover `r3` on GameCube.
3. Call through the function's own type (or give the function the type it is
   stored as: a display callback takes `(CameraId, void*)`).

Regenerate after fixes (both versions; section 2 needs a link that gets past
section 1):

```bash
ninja -C build-web-us ttyd > link-us.txt   # configured with -DCMAKE_EXE_LINKER_FLAGS=-Wl,--error-limit=0
emcmake cmake -S . -B build-web-audit-G8ME01 -G Ninja -DTTYD_VERSION=G8ME01 -DTTYD_BACKEND=headless -DTTYD_PTRWIDTH_WARNINGS=ON
ninja -C build-web-audit-G8ME01 -k 0 ttyd > audit-us.txt
python tools/port/web_abi_audit.py US=build-web-us,link-us.txt,audit-us.txt JP=build-web-jp,link-jp.txt,audit-jp.txt
```

## Sound names and ids (no change needed)

`include/sfx_name_word.h` tells a sound name (a pointer) from a sound id by
value: a name is at 0x80000000 or higher, as on GameCube. The web build puts
all of its memory there (`-sGLOBAL_BASE=2147483648`), at the cost of 2 GiB of
address space that is never touched. If the decomp ever tells them apart
another way (ids are below 0x08000000), the web build could start its memory
low, which matters on phones.
